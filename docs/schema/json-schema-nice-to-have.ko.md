19. Nice to Have: 미래 개선 아이디어 목록 (일단 반영하지 않는다)
당장은 출시를 위해 킵해두고, 추후 업데이트 시 고려할 리스트입니다.

AI 기반 개인화 일기 (2번 아이디어): 플레이어가 선택한 feedback 데이터를 LLM에 넣어 켄의 시점으로 하루를 회고하는 시스템.

성향 분석 리포트: 플레이어가 선택한 타입(GROWTH, REALIST 등)의 비중을 분석하여 '당신은 실속파 유학생' 같은 타이틀 부여.

시각적 타임라인: Day별로 주요 backgroundKey 이미지를 썸네일로 나열하여 정착 과정을 한눈에 보여주는 UI.

English 보관함: GROWTH 선택지에서 배운 영어 표현들을 퀴즈 형식으로 다시 풀어보는 복습 모드.

서머리 시스템 구축 아이디어 분석
1. 팁(Tip)을 활용한 범용적 가이드
아이디어: 사용자가 어떤 선택을 했더라도 상관없이, 해당 에피소드에서 반드시 알아야 할 '핵심 정보'를 팁 형식으로 제공하는 것입니다.

효과: 선택 결과와 관계없이 "밴쿠버 생활 지식"을 전달하므로 논리적 오류가 생길 리스크가 가장 적습니다.

구현: node.tip 데이터를 수집하여 "오늘의 밴쿠버 생존 일지" 섹션으로 구성합니다.

2. 피드백(Feedback)을 활용한 AI 서머리
아이디어: 플레이어가 선택한 각 노드의 feedback 텍스트들을 AI에게 입력값으로 주고, 이를 1인칭 시점의 일기 형태로 재구성하는 것입니다.

효과: "나는 오늘 짐을 잃어버렸지만 마크의 곰돌이 티셔츠 덕분에 웃을 수 있었다"처럼 플레이어의 경험이 반영된 고유한 결과물을 만들어줍니다.

3. 상황(Situation/Title)과 팁의 결합
아이디어: 1번과 유사하지만, 단순히 지식을 나열하는 게 아니라 "Day 2: 핸드폰을 만들고 집을 찾아보았다"라는 상황적 맥락 안에 팁을 녹여내는 것입니다.

비교: 1번이 '단답형 팁 모음'이라면, 3번은 '스토리텔링형 요약'에 가깝습니다.

4. 종합 의견 및 추천 설계 (The Best Practice)
AI의 자유도를 제어하면서도 개인화된 느낌을 주려면 "템플릿 기반의 AI 생성" 방식이 가장 안정적입니다.

추천하는 Summary 구조 (type: "SUMMARY")
활동 요약 (상황 이용):

Day 내의 모든 situation.title을 연결하여 "오늘 켄은 [공항 입국]을 하고 [짐 분실]을 겪은 뒤 [마크의 집]에 도착했습니다"라고 명시합니다.

개인화된 일기 (피드백 이용):

AI에게 "사용자가 선택한 피드백들을 기반으로 오늘 켄의 기분과 소감을 3문장 이내로 작성해줘"라고 요청합니다.

이때 사용자 보정 내역에 따라 인종차별이나 극단적인 표현은 철저히 배제하도록 설정합니다.

지식 정리 (팁 이용):

"잊지 마세요!" 섹션을 만들어 그날 마주친 tip들을 보여줍니다.

Summary 시스템 적용 예시
플레이어가 Day 2에서 '은행 먼저 가기(ID 9003)'와 '데이터 대장(ID 10)'을 선택했다면 AI는 다음과 같이 요약합니다.

[Day 2: 밴쿠버 정착의 첫 단추]

오늘의 발자취:

의욕 넘치게 은행을 먼저 찾았지만, 번호가 없어 당황했던 아침이었습니다.

결국 통신사 매장에서 '데이터 대장' 넉살을 부려 10GB를 추가로 얻어냈죠!

켄의 일기:
"캐나다 시스템은 생각보다 까다롭네요. 번호 하나 없다고 은행 업무가 막힐 줄이야... 그래도 마크 브로 덕분에 위기를 넘기고 공짜 데이터까지 얻으니 밴쿠버 생활, 해볼 만 한 것 같습니다!"

생존 꿀팁:

캐나다 번호는 온라인 신분증과 같으니 1순위로 만드세요.

통신사 가입 시 숨겨진 프로모션을 꼭 물어보세요.

결론: 사용자님의 아이디어 중 2번(피드백 활용 AI)을 메인으로 하되, 1번(팁)과 3번(상황)을 고정적인 데이터로 배치하여 신뢰도를 높이는 하이브리드 방식이 가장 좋습니다.

이렇게 하면 AI가 조금 이상한 말을 하더라도 고정된 '상황'과 '팁' 데이터가 중심을 잡아주어 전체적인 퀄리티가 유지됩니다. 이 요약 시스템을 위한 SUMMARY 전용 노드 구조를 하나 짜드릴까요?
